# 同行计划 · tongxing-plan

兰州大学队伍二｜面向大学生多人出行的情境感知协同决策与任务执行助手。

把分散的时间、预算、出发地、交通与偏好整理成可比较、可确认的共享行程。第一周固定演示：兰州校园出发，四人周末半日游，一个硬约束冲突，一次模拟降雨及室内替代预览。

> 当前为仓库初始化阶段（2026-11-16）。目录、协作模板与交付入口已建立；业务代码、数据契约、合成样例和可点击原型尚待各负责人提交，不能将本仓库视为已通过第一周验收。

## 目录与分工

```text
.github/    任务模板、PR 模板
docs/       项目说明、原型入口、验收记录、待确认决定
algorithm/  B：候选硬约束检测、固定用例与测试
core/       A：状态流转与降雨影响分析
tests/      A：状态及变更测试；B/C 复跑
scripts/    A：固定场景终端演示
```

## 获取代码与复现入口

```sh
git clone https://github.com/Ludywusy/tongxing-plan.git
cd tongxing-plan
```

第一周 A/B 模块使用 Python 标准库；建议团队统一 Python 3.11 或更新版本。业务文件提交后，从仓库根目录运行：

```sh
# B：候选约束测试
python -m unittest discover -s algorithm -p "test_*.py"

# A：状态与变更测试
python -m unittest discover -s tests -p "test_*.py"

# A：共享固定样例演示
python -m scripts.demo_trip_flow
```

**当前状态：以上业务测试与演示尚未实现。** 空目录可能报告 `Ran 0 tests`，不代表测试通过；演示模块在 A 提交前不可运行。联验时必须登记提交 SHA、实际测试数、结果和复核人。

## 数据与演示约定

- 目标契约：`schemas/trip-input.schema.json`；目标样例：`fixtures/demo-trip.json`。两者待 C 提交并于周三由 A/B/C 对齐。
- 匿名成员 ID、候选 ID、行程节点 ID 保持稳定；金额使用整数分，时间使用带时区的 ISO 8601，时区为 Asia/Shanghai。
- 固定样例包含四名匿名成员、三套可比较候选、失败输入和降雨替换情景；来源、更新时间及模拟标记不可省略。
- 事实数据不得冒充实时信息；模型抽取结果须经规则校验及用户确认。
- 问卷逐行答卷、撤回码和识别信息仅存团队受限资料区。公开仓库只收汇总、匿名摘要和明确标注的合成样例。
- 不读取私人聊天；日历导出、通知复制等对外操作按产品要求二次确认；支付、预订和取消由用户完成。
