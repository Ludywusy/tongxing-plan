# 《同行计划》MVP 范围与需求证据

面向从兰州校园出发的 4–6 人周末半日或一日游。首周以四人半日游验证一次预算冲突、全员确认和一次降雨替换。Android 在一台真机断网切换四个模拟身份，Python 可独立复跑同一合成样例。第二周联机验证以四台 Android 手机各用独立身份操作同一房间为准。

来源为更新后的 A/C/D 第一周任务书。任务书援引《同行计划-1(1).pdf》2026-11-14 执行版第 2 页第二、三节的状态、变化与授权要求，以及第 3 页第六节的首周调研与原型要求。首周队内以匿名问卷替代原定 8–10 组访谈，目标为至少 30 份有效答卷及 8 个去重的独立事件。当前待 D 提供实际统计与匿名证据。

| 需求 | 优先级与范围 | 可观察的验收动作 | 问卷证据 |
| --- | --- | --- | --- |
| MVP-01 建组与独立填报 | P0，首周 Android 单机四身份。Python 校验四人提交门槛 | 切换 `m01` 至 `m04`，分别填写时间、个人预算、交通、兴趣及禁忌，再切回核对各自数据和提交状态。缺成员时保留回填入口 | 待 D 关联多成员协调案例和题目分母 |
| MVP-02 对比候选并解释硬冲突 | P0，首周 Android 与 Python | 展示三张候选卡。`c01` 可查看说明，指出 `m01` 承担 81 元、上限 80 元、超 1 元。可行候选可选，缺项候选提示回填。兴趣用于比较 | 待 D 关联时间、预算、交通及硬软区分案例 |
| MVP-03 同版本确认与执行 | P0，首周 Android 与 Python | 四人确认同一可行候选和版本后才能开始。缺确认、改选后的旧确认或执行前的无效操作可复验。重复确认只计一次 | 待 D 关联确认方式案例和题目分母 |
| MVP-04 降雨后的局部调整 | P0，首周 Android 与 Python | 触发模拟降雨，仅命中 `c02-n02`。预览阶段 `change_pending` 展示同一时段的室内替代 `c02-n02-r1` 和三个保留节点。取消、替代不可行或过期预览保留当前行程。有效替代由发起人确认后生成 `v2` | 待 D 关联临时变化、处理及确认的事件 |
| MVP-05 授权后分享 | P0，首周 Android 模拟 | 显示待分享内容和外部写入二次确认。取消后保留已确认版本 | 待 D 关联通知和确认案例 |
| MVP-06 真实房间与偏好同步 | P0，第二周四机联机 | 四台 Android 手机以不同成员加入同一房间，分别提交。四台设备读到同一份房间状态、4/4 提交进度和约束汇总 | 待 D 关联实际成员提交与反复核对的案例 |
| MVP-07 POI 与规划基线 | P1，第二周 | 用带来源和许可的兰州周边 POI 小样产生可复跑的候选输入，逐人校验硬约束，再比较软偏好 | 待 D 关联地点、天气、营业和费用案例 |

首周的地点、路线、费用、天气及授权交互采用合成数据。真实天气与营业查询、完整重规划、联网候选确认及变更按后续契约推进。支付、预订和取消由用户完成。

D 在 `research/survey-analysis.md` 登记回收时点、有效数、事件数和各题分母，在 `research/needs.md` 提供匿名答卷或事件编号和摘要。收到后为每条需求补上编号与观察，分开记录实际发现和待验证假设。逐行答卷保存在受限资料区。
